# YouTube視聴改善アプリ — プロダクト仕様

このドキュメントは開発開始時にユーザーから共有された引き継ぎ資料を元にした初期仕様であり、Issue #1（Phase 1 PoC）等、以降の開発の出発点として扱う。

## 1. 概要

お気に入りのYouTubeチャンネルをAIが定期巡回し、新着動画を検知する。新着動画について文字起こしを取得し、AIで要約・重要度判定を行い、LINEでユーザーへ通知する。

コンセプト: YouTubeを自分で視聴するのではなく、AIに先に視聴・整理させ、重要な情報だけ受け取る。単なるYouTube要約サービスではなく、将来的には「個人向け情報収集エージェント」へ発展させる。

## 2. MVP機能

### 2.1 お気に入りチャンネル登録

ユーザーが監視対象となるYouTubeチャンネルを登録する。MVPでは管理画面を作らず、ユーザーがYouTube上でチャンネル登録（サブスクライブ）している一覧をOAuth経由で自動取得し、監視対象とする（`backend/src/lib/subscriptions.js`）。将来的にはWeb UIから個別に登録・除外可能にする。

### 2.2 新着動画検知

定期的にYouTube Data APIを利用して、登録チャンネルの新着動画を確認する。重複通知を防ぐため、処理済み動画IDを保存する（`backend/data/processed-videos.json`）。

### 2.3 文字起こし取得

新着動画から文字起こしを取得する。優先順位: (1) YouTubeで提供されている字幕・自動生成字幕、(2) 利用できない場合は別途STTを検討。

注意事項:
- 字幕が存在しない動画がある
- 自動生成字幕が利用可能になるまで時間差がある
- ライブ動画などは通常動画と扱いが異なる
- YouTubeの利用規約/APIポリシーを遵守する

MVPでは、まず「取得可能な字幕を利用する」方式を優先する。

## 3. AI処理

取得した文字起こしをLLM（Claude/Gemini/OpenAI等）へ渡し、以下を生成する。

- **要約**: 3行要約
- **重要度**: 5段階
- **視聴推奨度**: ユーザーにとって実際に動画を見る価値があるかの判定（5段階）

将来的にはユーザーの過去の視聴・保存・興味分野を学習し、パーソナライズ（関連度%）を行う。

## 4. LINE通知

AI処理が完了した動画をLINE Messaging APIで通知する。通知イメージ:

```
【YouTube新着】
○○氏が新しい動画を公開しました。
「AIエージェントの今後」
📝 要約
・AIエージェントの自律性が向上
・MCP連携が普及
・複数エージェント協調が重要に
⭐ 重要度：★★★★☆
👀 視聴推奨：★★★★★
▶ 動画を見る
```

## 5. アーキテクチャ（MVP）

常設のクラウドインフラ（EventBridge/Lambda/DynamoDB等）は使わず、GitHub Actionsの定期実行（schedule）で完結させる。処理済み動画IDや要約結果はリポジトリ内のJSONファイルで管理する。

```
GitHub Actions (schedule)
     ↓
YouTube Data API（新着動画確認）
     ↓
処理済み動画IDと比較（backend/data/processed-videos.json）
     ↓
文字起こし取得
     ↓
LLM API（要約・重要度・視聴推奨度）
     ↓
LINE Messaging API（通知）
     ↓
処理済み動画IDを更新してコミット
```

将来的にチャンネル数・処理量が増えた場合は、`docs/standard-tech-stack.md`の標準構成（Lambda + API Gateway + DynamoDB）への移行を検討する。

## 6. エラー処理

基本方針: 1動画の処理失敗でシステム全体を停止させない。エラーはログに残し、処理済みとしてマークせず次回実行時にリトライする。

## 7. 開発フェーズ

- **Phase 1（Issue #1）**: 固定チャンネル1つでの新着検知→文字起こし取得→LLM要約→LINE通知のE2Eパイプライン
- **Phase 2**: チャンネル登録管理、処理済み動画管理の強化、エラーリトライ、通知フォーマット改善、1日ダイジェスト
- **Phase 3**: パーソナライズ（視聴履歴・興味分野の学習）
- **Phase 4**: LINEからの対話によるAI動画アシスタント
- **Phase 5**: YouTube以外の情報源（ニュース・RSS・GitHub・Web・X）への拡張（情報収集エージェント化）

## 8. 開発上の重要な考え方

- YouTube APIの利用制限を考慮する
- 字幕取得不能な動画を前提にする
- 1動画の失敗で全体を止めない
- 処理済み動画をJSON（将来的にはDB）で管理する
- LLMへの入力サイズを制御する
- APIキー・LINEトークン等をコードに埋め込まない（GitHub Actions Secretsで管理）
- YouTubeおよび各APIの利用規約を確認する
- MVPではWeb UIを作り込みすぎない
